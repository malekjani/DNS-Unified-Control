# نصب هدایت‌شده DNS Unified Control v0.10.1

## هدف

نصب از صفر روی هر VPS پشتیبانی‌شده بدون نیاز به ویرایش کد و بدون واردکردن IP/دامنه به‌صورت آرگومان اجباری. مسیر معمول **فقط یک دستور** دارد:

```bash
cd /root/dns-unified-control
sudo bash install.sh
```

اجرای این دستور ابتدا `scripts/fresh-install.sh --guided` را شروع می‌کند. دستور زیر نیز معادل است:

```bash
sudo bash scripts/fresh-install.sh
```

گزینه‌های پیشرفتهٔ پیشین برای مدیریت خودکار یا بررسی بدون نصب همچنان وجود دارند:

```bash
bash scripts/fresh-install.sh --audit
bash scripts/fresh-install.sh --audit --domain m2m.diy --ip 13.39.238.230
sudo bash scripts/fresh-install.sh --guided --domain m2m.diy --ip 13.39.238.230
sudo bash scripts/fresh-install.sh --install --domain m2m.diy --ip 13.39.238.230
```

## مراحل نصب‌کننده

0. **ارزیابی فقط‌خواندنی**: توزیع سیستم‌عامل، systemd، apt، نصب قبلی، دیسک، RAM، Swap، پورت UDP/53 و TCP/1080,8088,80,443. خطاهای `BLOCK` مانع ادامه‌اند و نصب تغییری ایجاد نمی‌کند. نبود دامنه و IP در مرحله ارزیابی مانع نیست.
1. **دامنهٔ پایه**: دامنه با اعتبارسنجی واقعی درخواست می‌شود؛ مثلاً `m2m.diy`.
2. **IP عمومی VPS**: مقدار از پنل ارائه‌دهنده خوانده و وارد می‌شود؛ برای AWS EC2، آدرس خصوصی `ens5` را وارد نکنید. IP عمومی مانند `13.39.238.230` در AWS ممکن است با NAT به آدرس خصوصی متصل شود.
3. **Cloudflare (اختیاری)**: دریافت Token به‌شکل مخفی با `getpass` و فقط بررسی **Zone Read** برای دامنه انتخاب‌شده. Token چاپ، در فایل، آرگومان، متغیر محیطی یا `instance.json` ذخیره نمی‌شود. این مرحله **هیچ رکورد DNS را تغییر نمی‌دهد**. در زمان انتقال DNS مجدداً Token درخواست می‌شود؛ برای سایر Providerها می‌توان این مرحله را رد کرد.
4. **منابع و هشدارها**: در RAM کم و نبود Swap، امکان ساخت Swap دوگیگابایتی با اجازهٔ صریح. `systemd-resolved` روی Loopback به‌عنوان هشدار شناخته می‌شود، اما هیچ تغییر خودکاری روی `/etc/resolv.conf` یا سرویس Resolver اعمال نمی‌شود. باید قبل از روشن‌کردن موتور روی UDP/53، تعارض را به‌صورت ایمن برطرف کرد.
5. **موتورهای اضافی**: انتخاب اختیاری نصب موتورهای دیگر. نصب پایه Soar/NoizDNS را مطابق سیاست فعلی آماده می‌کند؛ برخی موتورهای سنگین/دارای وابستگی ممکن است نیازمند بررسی جداگانه باشند.
6. **ارزیابی نهایی و تأیید**: خلاصهٔ دامنه، IP، نصب موتورها، Swap و سیاست DNS نشان داده می‌شود؛ سپس عبارت `INSTALL-FRESH-<domain>` درخواست می‌شود. پس از تأیید، شناسه Instance، پیش‌نیازها، Web/Agent، Dante، کلیدهای جدید و پروفایل‌ها ایجاد می‌شوند. رمز ادمین نیز طبق نصب اصلی به‌صورت تعاملی درخواست خواهد شد.

## قواعد ایمنی

- این نصب **Cloudflare را تغییر نمی‌دهد** و **موتور DNS را روی UDP/53 روشن نمی‌کند**.
- در صورت وجود نصب قبلی، نصب تازه متوقف می‌شود؛ `--resume` تنها برای ادامهٔ همان Instance با همان IP و دامنه کاربرد دارد. برای نصب قبلی از `upgrade.sh` استفاده کنید.
- کلیدها، رمزهای Dante و MFA در نصب جدید مستقل از سرور قدیمی ایجاد می‌شوند. کلاینت‌های قبلی بدون انتقال کلیدها معتبر نیستند.
- برای تغییر دامنهٔ زنده ابتدا پنل و کلاینت‌های جدید را تست کنید؛ سپس انتقال کنترل‌شدهٔ رکوردهای `panel` و `ns` انجام شود. سرور قدیمی را تا تست نهایی برای Rollback نگه دارید.
- HTTPS و TOTP با بررسی DNS و ارائه‌دهنده، پس از نصب پایه تکمیل می‌شوند. HTTPS پیش از انتقال رکوردها خودکار فعال نمی‌شود. هیچ یک از ۹ موتور صرف نصب بسته به‌معنای تست‌شده بودن نیست.
- ابزار فعلی عمدتاً برای Ubuntu 24.04 LTS و Debian 12/13 با apt و systemd آزمایش شده است. نصب کامل، Rollback اتمیک و تست زنده روی محیط AWS در این نسخه آزمایش نشده‌اند.

## کار با سرور فرانسه

```bash
cd /root
unzip -tq DNS-Unified-Control-v0.10.1-Guided-Product-Installer.zip
unzip -oq DNS-Unified-Control-v0.10.1-Guided-Product-Installer.zip
cd dns-unified-control
python3 scripts/verify-release.py
sudo bash install.sh
```

در Wizard مقدار `m2m.diy` و `13.39.238.230` را وارد کنید. اگر Token فعال Cloudflare با دسترسی Zone Read ندارید، مرحله بررسی Token را رد کنید. در VPS با ~909 MiB RAM، ساخت Swap می‌تواند به بیلد موتورها کمک کند. بعد از پایان نصب، با پورت Forward امن `8088` وارد پنل شوید و MFA را پیکربندی کنید. انتقال Cloudflare عملیات مستقل بعدی است.
