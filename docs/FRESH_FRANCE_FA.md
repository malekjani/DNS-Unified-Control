# نصب صفر تا صد DNS Unified Control روی VPS جدید فرانسه

**بسته:** Fresh VPS Installer (بر پایه DNS Unified Control 0.9.8). **مقصد:** جایگزینی سرویس قبلی `m2m.diy` با IP جدید. **هدف:** اجرای ارزیاب اولیه و سپس نصب مرحله‌ای، نه بازگردانی بکاپ روی سرور تازه.

## مرزهای قطعی

- نصب تازه رمز مدیریت وب، TOTP، کلیدهای Noise/Ed25519/TLS و اعتبارنامهٔ Dante **جدید** تولید می‌کند. کلاینت‌ها و پروفایل‌های قبلی سازگار نیستند؛ قبل از انتقال `ns.m2m.diy` باید بستهٔ کلاینت جدید تولید و پخش شوند. نام دامنهٔ یکسان جایگزین کلید قبلی نمی‌شود.
- نصب اولیه **هیچ رکورد Cloudflare را تغییر نمی‌دهد** و **هیچ موتور DNS را Start نمی‌کند**. فقط یک Dante مشترک و خصوصی روی `127.0.0.1:1080` نصب می‌شود.
- دامنهٔ `m2m.diy` برای سرور فرانسه در فایل پروفایل محلی ثبت می‌شود. NSهای ۹ موتور در Cloudflare و nameserver رجیسترار حفظ می‌شوند. تنها دو رکورد A به ترتیب منتقل می‌شوند: `panel.m2m.diy` سپس `ns.m2m.diy`.
- نصب خودکار Soar و NoizDNS توسط `install.sh` انجام می‌شود. بقیه موتورهای پشتیبانی‌شده با `--with-engines` نصب می‌شوند؛ SlipStream نیاز به اقدام تأییدشدهٔ جدا و XDNS نیاز به بررسی Xray دارد. عبارت «همهٔ موتورهای آماده» به معنی «همهٔ موتورهای تأییدشده» نیست.
- سرور فعلی `188.132.174.249` تا پایان آزمون و زمان کش DNS روشن بماند. برگشت DNS به‌تنهایی کلاینت‌هایی را که کلید جدید دارند با سرور قدیمی سازگار نمی‌کند؛ نسخه‌های قدیمی کلاینت و فایل‌هایشان را برای Rollback نگه دارید.

## مرحله ۰: SSH مستقل و ارزیابی اولیه

IP واقعی فرانسه را از پنل ارائه‌دهنده مشخص کن؛ از اتصال SSH با IP استفاده کن، نه hostname دامنه‌ای که هنوز به سرور قدیمی اشاره می‌کند. قبل از تغییر Firewall، امکان کنسول Recovery ارائه‌دهنده را بررسی کن. پورت‌های مورد نیاز: TCP پورت SSH، UDP/53 برای موتور انتخاب‌شده، TCP/80 و 443 برای HTTPS. Dante نباید عمومی شود.

```bash
cd /root
unzip -tq DNS-Unified-Control-v0.9.9-France-Fresh-Install.zip
unzip -oq DNS-Unified-Control-v0.9.9-France-Fresh-Install.zip
cd dns-unified-control
bash scripts/fresh-install.sh --audit --domain m2m.diy --ip NEW_FR_IP
python3 -m duc.fresh_setup audit --domain m2m.diy --ip NEW_FR_IP --json
```

ارزیاب هیچ چیزی نصب یا تغییر نمی‌دهد. خروجی `BLOCK` یعنی نصب متوقف شود؛ `WARN` به معنی اقدام یا تأیید دستی است. موارد بررسی‌شده: OS، systemd، apt، نصب قدیمی، فضای دیسک، RAM و swap، listener مربوط UDP/53، IPv4 هدف و هشدارهای مهاجرت. ارزیاب **سرعت و دسترسی واقعی DNS Resolver، GitHub و فایروال شرکت ارائه‌دهنده را تضمین نمی‌کند**.

اگر فقط Ubuntu 24.04 / Debian 12/13 و منابع کافی داری، نصب را شروع کن. هیچ‌وقت بدون آگاهی محتویات `/etc/resolv.conf` یا فایروال SSH را خودکار تغییر نده.

## مرحله ۱: نصب کنترل‌شده بر اساس ارزیاب

```bash
sudo bash scripts/fresh-install.sh --install --domain m2m.diy --ip NEW_FR_IP
```

دستور از تو عبارت `INSTALL-FRESH-m2m.diy` را می‌خواهد؛ پس از آن بستهٔ موجود را نصب می‌کند. `install.sh` پیش‌نیازهای Python و سرورهای اجباری Soar/NoizDNS را نصب می‌کند. سپس Dante مستقل روی `127.0.0.1:1080` نصب/احراز می‌شود و پروفایل‌های ۹ موتور به `m/r/d/n/v/s/i/c/x.m2m.diy` تغییر **محلی** می‌کنند. هیچ‌کدام فعال نمی‌شوند. تمام رازها در فرانسه جدید هستند.

برای نصب سایر موتورهای ممکن (بدون فعال‌سازی):

```bash
sudo bash scripts/fresh-install.sh --install --domain m2m.diy --ip NEW_FR_IP --with-engines --resume
```

این شکل دوباره `install.sh` را هم اجرا می‌کند، بنابراین بهتر است از همان ابتدا `--with-engines` را به دستور اول اضافه کنی اگر واقعاً به نصب سایر موتورهای سبک نیاز داری. `--resume` فقط برای ادامهٔ همین VPS تازه است؛ روی سرور قبلی استفاده نکن. در صورت شکست نصب بر اثر شبکه، پس از رفع مشکل با `--resume` ادامه بده.

## مرحله ۲: بررسی وضعیت فرانسه و وب پنل

```bash
sudo bash scripts/fresh-install.sh --postcheck --domain m2m.diy --ip NEW_FR_IP
sudo ss -lunp '( sport = :53 )'
```

تا وقتی خودت یک موتور را فعال نکرده‌ای، UDP/53 ممکن است آزاد باشد. سپس از **Debian کلاینت**:

```bash
ssh -N -L 18088:127.0.0.1:8088 root@NEW_FR_IP
```

به `http://127.0.0.1:18088` برو، رمز جدید پنل را امتحان کن و TOTP جدید را راه بینداز. روی VPS، وضعیت `dante status` باید `ready=true` و `auth_verified=true` باشد. کلید و رمز را در چت ارسال نکن.

## مرحله ۳: کلاینت‌های جدید، یک موتور و آزمایش مستقل

از Web/TUI فقط یک موتور سازگار مثل NoizDNS را Start کن. برای موتور انتخابی یک کلاینت **جدید** (Native یا SlipNet) بساز. پروفایل و کلید عمومی قدیمی NoizDNS برای سرور جدید معتبر نیست. قبل از تغییر رکورد `ns`، با Resolver مستقیم `NEW_FR_IP:53` تست ابتدایی انجام بده؛ این **تست Recursive واقعی نیست**. برای SlipNet از `--dns NEW_FR_IP:53` همراه با URI **جدید** استفاده کن. پاسخ HTTPS باید IP فرانسه را نشان دهد و رمز غلط باید رد شود.

آزمایش از `1.1.1.1:53` را فقط **پس از** انتقال `ns.m2m.diy` می‌توان به‌عنوان تست کامل Resolver عمومی در مسیر جدید استفاده کرد. سیستم قدیمی را برای fallback نگه دار.

## مرحله ۴: انتقال دو مرحله‌ای Cloudflare با تأیید

در سورس کامل اسکریپت `scripts/fresh-cloudflare-cutover.py` موجود است. پیش‌فرض آن Dry Run است؛ Token را با getpass می‌گیرد و ذخیره نمی‌کند. **فقط** رکورد A از قبل مدیریت‌شده و DNS-only را تغییر می‌دهد و IP قبلی را کنترل می‌کند. ۹ رکورد NS واگذاری را تغییر نمی‌دهد. روی Debian مورداعتماد یا خود VPS جدید:

```bash
python3 scripts/fresh-cloudflare-cutover.py --label panel --from-ip 188.132.174.249 --to-ip NEW_FR_IP
python3 scripts/fresh-cloudflare-cutover.py --label panel --from-ip 188.132.174.249 --to-ip NEW_FR_IP --apply
```

پس از Cutover پنل، ابزار Caddy `scripts/setup-panel-https.sh` را **به‌صورت تعاملی** اجرا کن و با `curl -I https://panel.m2m.diy` و ورود TOTP بررسی کن. این اسکریپت خودش تنظیم DNS پنل را با توکن Cloudflare تأیید می‌کند. سپس **فقط بعد از تست تونل جدید**:

```bash
python3 scripts/fresh-cloudflare-cutover.py --label ns --from-ip 188.132.174.249 --to-ip NEW_FR_IP
python3 scripts/fresh-cloudflare-cutover.py --label ns --from-ip 188.132.174.249 --to-ip NEW_FR_IP --apply
```

`ns.m2m.diy` DNS-only بماند. `panel.m2m.diy` هم در پیکربندی قبلی DNS-only است. کش Recursive ممکن است برای مدتی IP قدیمی را نگه دارد. حذف سرور قدیم زودهنگام است.

## مرحله ۵: بازیابی مسیر قدیمی

اگر مشکل قابل‌توجهی پیدا شد، ابتدا `ns` و بعد `panel` را با تعویض `--from-ip NEW_FR_IP --to-ip 188.132.174.249 --apply` برگردان. توکن API هر بار فقط هنگام اجرا درخواست می‌شود. اگر کلاینت‌ها کلید جدید دارند، برای رجوع به سرور قبلی باید از **پروفایل‌های قبلی** استفاده کنند. تغییر DNS، کلیدهای جدید را به کلیدهای قدیمی تبدیل نمی‌کند.

## محدودیت‌های مهم

- اجرای این ابزارها روی VPS فرانسه و شبکهٔ خارجی انجام نشده است. Preflight محلی جایگزین آزمایش دسترسی TCP/UDP از بیرون نیست.
- پورت 53 اگر با systemd-resolved یا سرویس DNS دیگری درگیر باشد، باید با تأیید دستی رفع شود؛ حذف خودکار resolver سیستم مجاز نیست.
- Upstreamهایی که کامپایل/دانلودشان شکست می‌خورد، با وضعیت ناموفق و قابل تکرار باقی می‌مانند؛ نسخهٔ برنامه تضمین‌کنندهٔ پشتیبانی عملیاتی تمام موتورهای تعریف‌شده نیست.
- راه امن‌تر برای مهاجرت بی‌اختلال این است که به‌جای نصب صفر، کلید و اعتبارنامه‌های قدیمی منتقل شوند؛ این بسته عمداً برای **نصب با هویت جدید** طراحی شده است.
