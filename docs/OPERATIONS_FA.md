# راهنمای عملیاتی DNS Unified Control v0.4.1

## وضعیت این نسخه

این بسته **مدیر سرویس‌های سمت VPS** است. تمام ۹ نوع موتور در کاتالوگ پنل تعریف شده‌اند و نصب‌کننده تلاش می‌کند باینری‌های همه را دریافت/کامپایل کند، اما تکمیل نصب و کارکرد هر موتور باید بر اساس خروجی `install-results.json` و Preflight بررسی شود. اتصال DNS از سمت اینترنت ایران، کلاینت، سرعت و Packet Loss در این نسخه تضمین یا آزمایش نشده‌اند.

## پیش‌نیازها

- VPS خارجی Debian/Ubuntu با IPv4 عمومی؛ دسترسی SSH/console مستقل و امکان ورودی UDP/53.
- دامنه ثبت‌شده که Nameserverهای اصلی آن به Cloudflare واگذار شده و Zone فعال باشد.
- API Token محدود Cloudflare با `Zone:Read` و `DNS:Edit` برای همان Zone؛ توکن را داخل تیکت، فایل پروژه یا چت ارسال نکنید.
- در نصب اولین نسخه، پیش از اجرا از سرور Snapshot/Backup بگیرید.

## نصب

```bash
unzip dns-unified-control-v0.4.1-multicore.zip
cd dns-unified-control
sudo bash install.sh
```

نصب‌کننده رمز حداقل ۱۶ کاراکتری می‌خواهد، تنظیم Cloudflare را پیشنهاد می‌دهد و برای نصب همه موتورهای خارجی جداگانه اجازه می‌گیرد. در حالت غیرتعامل:

```bash
# بعد از بررسی سورس اسکریپت‌ها و تهیه backup:
sudo DUC_INSTALL_ENGINES=1 DUC_INITIAL_PASSWORD='A_LONG_UNIQUE_PASSWORD' bash install.sh
```

**هشدار:** نوشتن رمز در خط فرمان یا سابقه shell می‌تواند آن را افشا کند؛ روش تعاملی ترجیح دارد.

## تفکیک DNS

یک `A` با نام `ns.DOMAIN` به IP عمومی VPS با Cloudflare DNS-only.

نه `NS` مستقل که همگی به `ns.DOMAIN` اشاره می‌کنند:

| موتور | زیردامنه |
|---|---|
| MasterDnsVPN | `m.DOMAIN` |
| SlipStream Rust | `r.DOMAIN` |
| DNSTT | `d.DOMAIN` |
| NoizDNS | `n.DOMAIN` |
| VayDNS | `v.DOMAIN` |
| Soar | `s.DOMAIN` |
| iodine | `i.DOMAIN` |
| dns2tcp | `c.DOMAIN` |
| XDNS/Xray | `x.DOMAIN` |

از زبانه DNS، دکمه «بررسی ۹ زیردامنه» را بزنید: سیستم با استفاده از Resolverهای `1.1.1.1` و `8.8.8.8`، NSهای مرجع دامنه اصلی را پیدا می‌کند، واگذاری NS را مستقیم از مرجع اصلی بررسی می‌کند و رکورد A را هم می‌سنجد. به این ترتیب خاموش‌بودن موتور باعث خطای کاذب در تشخیص واگذاری نمی‌شود. این **فقط مشاهده واگذاری DNS** است؛ پورت باز، سلامت تونل و موفقیت اتصال کلاینت را ثابت نمی‌کند. هر IP برگشتی را با IP واقعی VPS نیز تطبیق دهید.

## پنل

پنل فقط روی `127.0.0.1:8088` گوش می‌دهد. از سیستم شخصی:

```bash
ssh -N -L 8088:127.0.0.1:8088 root@YOUR_VPS_IP
```

سپس `http://127.0.0.1:8088` را باز کنید. SSH و پنل را روی همان تونل DNS که قصد خاموش‌کردنش را دارید قرار ندهید.

## Exclusive Mode

پنل یک موتور قبلی را متوقف می‌کند، اشغال پورت را بررسی می‌کند، موتور جدید را اجرا می‌کند و اگر سرویس پایدار نشد تلاش می‌کند به قبلی برگردد. **اتصال TCP جاری حفظ نمی‌شود**. تنظیم کلاینت در این نسخه خودکار عوض نمی‌شود. هیچ یک از unitهای `dns-unified@...` را دستی enable نکنید. `systemctl` دستی می‌تواند حالت exclusive را دور بزند.

## رفع مشکل

```bash
sudo bash diagnose.sh
cat /var/lib/dns-unified/install-results.json
sudo ss -lntup | grep ':53' || true
sudo journalctl -u dns-unified@vaydns -n 60 --no-pager
```

- Soar در حالت مستقیم یک پراکسی عمومی بدون حساب کاربری است. قبل از فعال‌سازی خطر استفاده غیرمجاز را ارزیابی کنید و صرفاً از مسیر خصوصی/محدود استفاده کنید.
- NoizDNS بعضی نسخه‌های باینری به شیوه pluggable transport کار می‌کنند؛ بدون تایید CLI `-udp` اجرای آن مسدود می‌شود.
- XDNS بخشی از FinalMask Xray است و باید یک JSON معتبر، سازگار با نسخه نصب‌شده داشته باشد.
- iodine یک تونل IP است و NAT و Routing مستقل می‌خواهد.
- DoH/DoT در VayDNS مربوط به سمت کلاینت‌اند؛ DoQ در این نسخه نصب نشده است.
- SlipStream Rust مخزن آرشیوشده دارد و به‌روزرسانی امنیتی تضمین نمی‌شود.
