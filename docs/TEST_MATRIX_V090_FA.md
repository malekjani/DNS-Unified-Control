# ماتریس فنی و آزمون‌های نسخهٔ 0.9.0

**تفکیک شواهد:** آزمون‌های خودکار Python در محیط توسعه اجرا می‌شوند، ولی تست میدانی نیازمند اتصال Debian به VPS واقعی و تعویض مدیریت‌شدهٔ Exclusive Mode است. ثبت گزارش موفق در پنل به‌معنای تأیید مستقل آن توسط سرور نیست.

| موتور | وضعیت Backend در 0.9.0 | وضعیت میدانی شناخته‌شده تا قبل از ارتقای 0.9.0 | آزمون بعدی |
|---|---|---|---|
| SlipStream Rust | raw TCP → Dante مشترک | **HTTPS/SOCKS5 موفق؛ خروج IP `188.132.174.249`** با تنظیمات فعلی VPS | baseline `duc_socks_probe.py` با ۵ درخواست؛ بدون قطع دسترسی |
| DNSTT | raw TCP → Dante مشترک، بدون کلاینت Gateway | قبلاً TCP/SSH تست شده؛ **SOCKS/Dante تأیید نشده** | تغییر موتور در پنل؛ کلاینت DNSTT 2080؛ تست احراز هویت و HTTPS |
| VayDNS | raw TCP → Dante مشترک؛ پارامترهای همگام Keepalive | قبلاً TCP/SSH تست شده؛ **SOCKS/Dante تأیید نشده** | تأیید یکسان بودن ورژن/کلید و timers؛ سپس SOCKS/HTTPS |

## ترتیب آزمون‌های واقعی

1. ثبت Baseline از SlipStream که اکنون فعال است؛ ذخیره وضعیت سرویس‌ها قبل از سوئیچ.
2. DNSTT و VayDNS را جداگانه به Shared Dante وصل کن؛ برای هر کدام تنها یک بار در Exclusive Mode به موتور مربوطه سوئیچ کن. کلاینت قبلی 2080 باید بسته باشد.
3. با `duc_socks_probe.py` روی Debian نام کاربری/رمز Dante را بدون ثبت در argv وارد کن؛ خروجی را از کانال SSH به VPS بفرست یا در مانیتورینگ paste کن.
4. به SlipStream برگرد و تست خروج IP را دوباره انجام بده تا برگشت‌پذیری ثابت شود.
5. dns2tcp و Soar را بعد از مرور مجوزهای public TCP و امنیت در پنجرهٔ آزمایشی جدا بررسی کن؛ هیچ‌یک به‌شکل خودکار به Dante وصل نمی‌شوند.
6. iodine را با bench دَه‌پروفایلی مقایسه کن. Ping/ICMP Loss صرفاً سطح IP را نشان می‌دهد، نه packet loss خام DNS.

## تعریف آمار

- `socks_connect_rtt_ms`: زمان TCP/احراز هویت/CONNECT سمت کلاینت، نه RTT خام DNS.
- `http_ttfb_ms`: از ارسال درخواست HTTP تا اولین بایت پاسخ در همان آزمایش.
- `http_throughput_bps`: فقط وقتی بدنهٔ پاسخ HTTP حداقل ۶۴ کیلوبایت است محاسبه می‌شود. باید از URL قابل‌اتکا با محتوای یکسان، مبدأ یکسان، مسیر یکسان و اندازهٔ مشابه استفاده کرد.
- `request_failure_pct`: شکست درخواست HTTPS؛ نباید با Packet Loss پروتکل DNS اشتباه گرفته شود.
- `icmp_packet_loss_pct`: نرخ loss واقعی Ping فقط برای iodine و فقط روی IP تونل.
- `raw_dns_packet_loss_pct`: در این نسخه **اندازه‌گیری نشده**؛ افزودن شمارندهٔ بسته در سمت موتور/کلاینت و exporter لازم است.

**رفتار ایمن ارتقا:** `upgrade.sh` صرفاً سورس پنل و Agent را نو می‌کند و سرویس موتور DNS جاری را تغییر نمی‌دهد؛ ساخت و جایگزینی باینری‌ها و سوییچ عملی نیازمند اقدام جداگانه است.
