# معیار تکمیل نصب Web / TUI در v0.10.5

برخلاف نسخه‌های قبلی، سلامت HTTP محلی برای اعلام Web READY کافی نیست.

- **TUI READY:** موتور برنامه، Agent API و Dante در localhost سالم‌اند. برای استفاده با SSH کافی است.
- **WEB INCOMPLETE:** اگر گواهی موجود نباشد، تاریخ آن مشکل داشته باشد، اعتبارنامه‌های تمدید مفقود باشند، مسیر واقعی TLS/443 به صفحه DUC تأیید نشود، یا رکورد A پنل به این Instance اشاره نکند.
- **WEB READY:** گواهی معتبر، تمدید قابل‌پیکربندی، مسیر HTTPS با CA معتبر و نمایش صفحه DUC، و پاسخ DNS پنل روی IP همین سرور همگی تأیید شوند.

`sudo bash install.sh` در Fresh، Upgrade و Repair دربارهٔ تکمیل گواهی با پاسخ `yes/no` می‌پرسد. کاربر اگر `no` بزند، TUI حفظ می‌شود ولی بخش Web ناقص گزارش می‌شود. اجرای دوبارهٔ همین دستور تلاش می‌کند بخش ناقص را تکمیل کند؛ بدون ساخت دوبارهٔ کلیدها یا Restart موتورهای DNS.

**مهم برای AWS فرانسه:** Xray روی TCP/443 و HAProxy روی TCP/80 هستند. دریافت گواهی DNS-01 این سرویس‌ها را قطع نمی‌کند، اما تا وقتی مسیر SNI و گواهی واقعاً به `127.0.0.1:8088` متصل نشده باشد، Web کامل نیست. اسکریپت خودسرانه پیکربندی Xray/HAProxy را تغییر نمی‌دهد. انتشار NS تونل‌ها عملیات جداگانه و پس از تست کلاینت باقی می‌ماند.

**تمدید:** در v0.10.4 گواهی با فایل توکن موقت ساخته می‌شد، بنابراین Certbot ممکن است برای تمدید به فایلی اشاره کند که حذف شده است. اعتبارنامهٔ دائمی فقط با رضایت صریح در مسیر root-only ذخیره می‌شود و با `certbot reconfigure` تمدید مجدد پیکربندی می‌شود. در صورت رد کردن ذخیره‌سازی یا خطا، Web `INCOMPLETE` باقی می‌ماند. خودکاربودن cron به معنای کارکرد تمدید نیست.
