# DNS Unified Control — کنترل یکپارچهٔ تونل‌های DNS

[English README](README.md) · [جزئیات Multi-Engine](docs/MULTI_ENGINE_P1_FA.md) · [تغییرات 0.10.6](CHANGELOG-v0.10.6.md)

**هدف پروژه:** ساخت یک پنل واحد برای نصب، راه‌اندازی، نظارت و مدیریت امن چندین موتور تونل DNS؛ بدون نیاز به پنل جداگانه برای هر موتور و بدون تغییرات غیرمنتظره روی سرویس‌های فعال سرور.

## قابلیت‌های اصلی

- **Web + TUI + Agent مشترک:** همهٔ رابط‌ها از یک هستهٔ مدیریت استفاده می‌کنند.
- **نصب و ارتقای کنترل‌شده:** دستور `sudo bash install.sh` با تشخیص Fresh، Resume، Repair و Upgrade؛ گزارش خطا، ثبت Checkpoint و تأیید `yes/no`.
- **Exclusive Mode:** اجرای یک موتور انتخاب‌شده؛ حالت پیش‌فرض امن.
- **Multi-Engine Mode:** یک DNS Router برای هدایت پرسش‌ها براساس Zone به چند موتور مستقل؛ این قابلیت در نسخهٔ 0.10.6 هنوز مرحلهٔ اول توسعه است.
- **Dante مشترک:** SOCKS5 احرازشده روی `127.0.0.1:1080` برای موتورهای سازگار.
- **مدیریت DNS و TLS:** بررسی Cloudflare، صدور و تمدید گواهی و کنترل صحت دسترسی عمومی پنل. کامل‌بودن TUI به معنی کامل‌بودن Web عمومی نیست.

## موتورهای منتخب Multi

`MasterDnsVPN`، `Soar`، `CottenDNS`، `SlipStream`، `NoizDNS`، `DNSTT` و `VayDNS`.

**محدودیت مهم:** CottenDNS در نسخهٔ فعلی فقط جایگاه آداپتور دارد و هنوز به‌صورت کامل نصب/آزمون نشده است. پشتیبانی واقعی هم‌زمان از تمام هفت موتور در سرور عملیاتی تأیید نشده. برای هر موتور نیاز به باینری، کلیدها، سازگاری پروتکل و تست کلاینت واقعی داریم.

## راه‌اندازی

پس از دریافت و استخراج بستهٔ سورس:

```bash
cd dns-unified-control
python3 scripts/verify-release.py
sudo bash install.sh --dry-run
sudo bash install.sh
```

بررسی بی‌خطر وضعیت Multi:

```bash
sudo /opt/dns-unified-control/.venv/bin/python -m ducmulti.cli plan \
  --mode multi --engines master,soar,cotten,slipstream,noizdns,dnstt,vaydns
```

**در وضعیت فعلی دستور اعمال Multi را روی VPS عملیاتی اجرا نکنید** مگر اینکه پیش‌نیازهای تمام موتورهای انتخاب‌شده و تست End-to-End تأیید شده باشند. نصب کد به‌معنای فعال‌سازی موتور DNS یا تغییر خودکار Cloudflare نیست.

## نقشهٔ راه

۱. آزمون و تکمیل واقعی Multi-Engine و بازگشت ایمن به Exclusive.

۲. تکمیل CottenDNS، انتخاب Resolver و پروفایل‌های Survival و Packet Loss.

۳. تکمیل HTTPS عمومی پنل در کنار سرویس‌های موجود 80/443.

۴. مدیریت حساب‌ها، سهمیه، وضعیت کاربر و گزارش‌گیری از درون خود پنل (بدون Soar-Server مستقل).

۵. اتوماسیون Release و تست‌های میدانی.

**امنیت:** هیچ توکن Cloudflare، کلید خصوصی، رمز عبور، فایل تنظیمات سرور یا اطلاعات MFA نباید در GitHub منتشر شود. `release-manifest.json` فقط یکپارچگی فایل را می‌سنجد، نه اصالت منتشرکننده.

**مجوز:** هنوز LICENSE سراسری برای سورس این محصول انتخاب نشده است. عمومی‌بودن مخزن به‌معنای مجازبودن کپی یا توزیع دلخواه کد نیست؛ مجوز پروژه‌های ثالث نیز باید رعایت شود.
